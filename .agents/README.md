# AI development rules & skills — nrscholar-frontend

This folder is the **single source of truth** for how AI coding assistants work in this repository.
Rules hold standards that are always on or scoped to file paths. Skills are step-by-step workflows
for recurring tasks (feature, bug fix, review, …).

## Layout

```
AGENTS.md                         entry point: project summary, non-negotiables, index
CLAUDE.md                         imports AGENTS.md for Claude Code
.agents/
├── README.md                     this file
├── sync.mjs                      generates the tool-specific copies below
├── rules/<name>.md               SOURCE: rules (Antigravity format: trigger / description / globs)
└── skills/<name>/SKILL.md        SOURCE: skills (Agent Skills format: name / description)

Generated by `node .agents/sync.mjs` (never edit by hand, they carry a GENERATED marker):
.cursor/rules/<name>.mdc                    Cursor rules
.github/instructions/<name>.instructions.md GitHub Copilot path instructions
.claude/rules/<name>.md                     Claude Code rules (always-on and path-scoped only)
.claude/skills/<name>/SKILL.md              Claude Code skills

Hand-written, tool-specific:
.github/copilot-instructions.md   Copilot summary (code review reads only this file)
.github/pull_request_template.md  PR description template
```

## How each tool picks them up

| Tool | Rules | Skills | How to invoke a skill |
| --- | --- | --- | --- |
| **Antigravity** | `AGENTS.md` + `.agents/rules/*.md` (native) | `.agents/skills/` (native) | Picked automatically by description, or ask: "use the bug-fixing skill" |
| **Cursor** | `AGENTS.md` + `.cursor/rules/*.mdc` | `.agents/skills/` (native) | Automatic, or type `/bug-fixing` in Agent chat |
| **GitHub Copilot** (VS Code agent mode, coding agent) | `AGENTS.md`, `.github/copilot-instructions.md`, `.github/instructions/*.instructions.md` | `.agents/skills/` (native) | Automatic, or `/bug-fixing` in Copilot Chat |
| **Claude Code** | `CLAUDE.md` → `AGENTS.md`, `.claude/rules/*.md` | `.claude/skills/` | Automatic, or `/bug-fixing` |

Notes:
- Copilot (VS Code) also scans `.claude/skills/`, so it may list a skill twice. The copies are identical.
- In VS Code make sure **Chat: Use AGENTS.md file** and **Agent Skills** are enabled (both are on by default in current versions).
- Copilot's code review on github.com reads `.github/copilot-instructions.md` and `.github/instructions/`.
- Rule triggers map as follows: `always_on` → Cursor `alwaysApply`, Copilot `applyTo: '**'`, Claude rule without `paths`.
  `glob` → Cursor `globs`, Copilot `applyTo`, Claude `paths`. `model_decision` → Cursor "apply intelligently",
  Copilot description-only, and Claude reads it on demand via the AGENTS.md index.

## Daily use

1. Open the repo in your tool. Rules load automatically.
2. Describe the task normally. For anything non-trivial, name the skill: *"Use the feature-development skill: add a streak badge to the progress screen."*
3. When the assistant presents an impact-analysis table, review it before approving edits.
4. Before opening a PR: *"Use the code-review skill on my branch"*, then *"use git-pr-preparation"*.

## Changing a rule or skill

1. Edit or add the file under `.agents/rules/` or `.agents/skills/<name>/SKILL.md`.
   - Rule frontmatter: `trigger: always_on | glob | model_decision | manual`, `description`, and `globs` (comma-separated) for `glob`.
   - Skill frontmatter: `name` (must equal the folder name, lowercase-hyphenated) and `description` (say *when* to use it).
2. Run `node .agents/sync.mjs`. It writes, updates and deletes the generated copies.
3. Commit the source and the generated files together, in a `docs(ai): …` PR.
4. `node .agents/sync.mjs --check` exits non-zero if copies are stale. It's suitable for CI.

Keep always-on rules short. Antigravity caps all always-on rules at about 20k tokens combined, and
every tool pays for them on every request. Put detail in glob or on-demand rules and in skills.

## Scope

These rules cover both the web app (`src/`) and the Expo mobile shell (`mobile/`). Path-scoped
rules load only for the matching part (for example `mobile-and-webview` for `mobile/**`). The
backend is a separate repository, so contract changes there need a linked PR.
